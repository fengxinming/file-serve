# 2026-08-25

## rem 双端适配改造（替代 vw 方案）

**背景**：原 vite.config.ts 使用 postcss-px-to-viewport（viewportWidth: 375），桌面端打开页面放大 5.1x（14px 正文 → 71.7px），且 `max-width: 960px` 被转成 256vw 失去约束。方案对比后确定用 rem + clamp 封顶。

**改动**：
- 依赖：移除 `postcss-px-to-viewport`，新增 `postcss-pxtorem@6.1.0` + `@types/postcss-pxtorem`（types/postcss-px-to-viewport.d.ts 已删除）
- `vite.config.ts`：postcss-pxtorem 配置 `rootValue: 16`，propList 排除 `!--*`（CSS 变量）、`!border*`（保护 Vant 1px hairline 细线）、`!top/right/bottom/left`、`!z-index`、`!flex-basis`；`selectorBlackList: [/^html$/]` 防根字号循环依赖；`mediaQuery: false`；`minPixelValue: 1`
- `src/app/style.css`：`html { font-size: clamp(16px, calc(100vw / 375 * 16px), 24px) }` — 375px 视口 1:1，562px 以上封顶 1.5x
- 业务 CSS 固定尺寸用**大写 PX 豁免**（postcss-pxtorem 官方约定，不转 rem）：App.vue 5 处（.browser max-width:960PX、.file-row__checkbox 18PX、.file-row__check 16PX、.file-row__meta 72PX/56PX、.file-row__meta--time 130PX）、UploadPanel.vue 2 处（.upload-panel__num 64PX×28PX、.upload-task__status 44PX）
- Vant 组件样式**参与 rem 转换**（不 exclude node_modules），与页面文字协调缩放

**验证**：`pnpm build` 通过；产物 CSS 确认 body 14px→.875rem、max-width 保持 960px、border 1px 保持物理值、html clamp 未被转换。生产模式 `node dist/file-serve.mjs` 3000 端口预览正常。

**环境注意（重要）**：WorkBuddy 沙箱有 safe-delete 保护，Vite build/dev 的 emptyOutDir 和依赖预构建（.vite/deps、deps_temp）清理 ≥50 文件会被拦截。规避：构建前 `mv dist /tmp/...`（不删除），dev 依赖预构建无法绕开时改用生产模式 serve 产物。
